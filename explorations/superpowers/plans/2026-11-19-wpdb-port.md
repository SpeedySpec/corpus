# `wpdb` port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** WordPress's `wpdb` in Rust (`speedyspec-wp-db`: every method as a command or query over the data layer,
its domain services, its hooks through the Rust Hook API) and as a native PHP `wpdb` class and `$wpdb` global
(`speedyspec-wp-db-php`), proven by `compat/wp-db` recordings replayed exactly on MySQL and by WordPress's own
database tests run against the native class.

**Architecture:** `WpDb` is the port's API and the handler of every command and query; it holds a `SqlStore` (the
`default` engine, wrapped in a timing Decorator), the `HookApi`, and two outbound ports: `WpdbState` (request state)
and `WpdbHost` (what only PHP's WordPress can do: `_doing_it_wrong`, `__()`, `error_log`, output, `wp_die`). Pure
domain services (`Prepare`, `PlaceholderEscape`, `TableNames`, `FieldFormats`, `CharsetRules`, `ServerCaps`,
`DbHost`) hold WordPress's rules. The PHP side is a facade class over native functions, as `WP_Hook` is; SQL text
from PHP is filtered, parsed, and executed as a `Statement`.

**Tech Stack:** Rust 1.99, edition 2024; plan 1's crates (`speedyspec-data`, `-data-query`, `-data-mysql`); the Hook
API crates (`speedyspec-wp-hooks`, `speedyspec-hooks`), `speedyspec-cqrs`, `speedyspec-container`, `speedyspec-php`,
`speedyspec-php-ext`, `speedyspec-compat`; `regex` (bytes API, for WordPress's regexes), `indexmap`,
`percent-encoding`. PHP 8.4 in the embedded runtime (property hooks).

**Spec:** `docs/superpowers/specs/2026-11-19-database-layer-design.md` ("The `wpdb` port", "The native `wpdb`
class", "Errors and logging", "Testing"). Plan index: `docs/superpowers/plans/2026-11-19-data-and-options-ports-index.md`.
Consumes plan 1: `docs/superpowers/plans/2026-11-19-data-layer-foundation.md`. WordPress's original:
`wp-includes/class-wpdb.php` of WordPress 7.1.5 (the pinned release); every "as WordPress does" below means that file.

## Global Constraints

- Work in a new worktree of `SpeedySpec/speedyspec-server` branched from plan 1's merged branch (or `origin/main`
  once it is merged), branch `feat/wpdb-port`. New crates go under `crates/`; the workspace needs no edit.
- Each crate's `Cargo.toml`: `edition.workspace = true`, `rust-version.workspace = true`, `license.workspace = true`,
  version `0.1.0`, a one-line `description`.
- **Do not edit `crates/speedyspec-php-runtime`.** The worker changes are requested in Task 16's note.
- Cross-plan names are fixed by the index and used exactly: `WpDb`, `WpdbState`, `MemoryWpdbState`, `TableNames`
  (`TableNames::name(&self, logical: &str) -> String`), `Prepare`, `PlaceholderEscape`, `CharsetRules`,
  `FieldFormats`, `OutputShape` (`Object`, `ObjectK`, `ArrayA`, `ArrayN`), `WpDbError`, `WpDbArea`,
  `WpDb::query_statement(&self, stmt: Statement) -> Result<QueryOutcome, WpDbError>`, message keys
  `SpeedySpec\WpDb\<Name>Handler`.
- `prepare()`, escaping, the insert/update helpers and every other rule of `wpdb` exist once, in Rust. The PHP
  facade converts arguments and results and holds no logic beyond that.
- Every statement reaches the store as a parsed `Statement` (`speedyspec_data_query::parse_one`); nothing executes
  SQL text.
- Column values reach PHP as strings or null with MySQL's bytes (`DbValue::to_mysql_text`), as mysqli gives them.
- Hook names and arguments are WordPress's: `query`, `incompatible_sql_modes`, `log_query_custom_data`,
  `pre_get_table_charset`, `pre_get_col_charset`; plus the Rust-only filter `speedyspec_query_statement`.
- User-visible strings (errors, notices) are copied verbatim from WordPress 7.1.5's `class-wpdb.php`; where the port
  has its own error (parse, unsupported, drop-in), its wording is given in the task.
- Patterns used here: Gateway and Facade (`wpdb` class over `WpDb`), Command / CQRS (messages), Decorator
  (`TimedSqlStore`, the query log), Strategy (`WpdbHost`, `WpdbState` adapters), Adapter (PHP twins), Observer (the
  hooks), Value Object (`DbHost`, `WpRow`, `TableNames`). No Repository here: `wpdb` is the Gateway the repositories
  of later ports sit beside.
- MySQL for tests: `docker run -d --name speedyspec-mysql -e MYSQL_ROOT_PASSWORD=password -e MYSQL_DATABASE=speedyspec_test -p 33306:3306 mysql:8.4`,
  `SPEEDYSPEC_TEST_MYSQL_URL=mysql://root:password@127.0.0.1:33306/speedyspec_test`. Cargo tests that need it are
  `#[ignore = "needs MySQL: set SPEEDYSPEC_TEST_MYSQL_URL"]`; `harness = false` tests that need it print
  `skipped: needs MySQL: set SPEEDYSPEC_TEST_MYSQL_URL` and exit 0 when it is unset.
- After Linux container test runs, delete that run's `target-linux*/` folder or Docker target volume.

## Review Focus

- **A query whose text does not start with its verb** (`/* tag */ INSERT ...`, `(SELECT ...)`): WordPress picks the
  return value and which counters to set by regex on the text, so such an `INSERT` returns `num_rows` (0) and leaves
  `rows_affected` and `insert_id` alone. The port classifies text the same way, by `QueryClass::of`, not by the
  parsed kind. Test in Task 7.
- **`get_var()` on an empty-string value**: WordPress returns null, not `''`. Test in Task 6.
- **Duplicate column names** (`SELECT a.id, b.id`): one field `id` at the first position holding the last value, in
  every shape, and `ARRAY_N` has one entry fewer than the column count; `OBJECT_K` keeps the first row per key. Test in
  Task 6.
- **`%` in prepared values** (`prepare("... LIKE %s", "50%")`): the placeholder escape is in `prepare()`'s output and
  gone from both the executed statement and `last_query`, also when no PHP callback is on `query`. The recorder
  normalises the per-request random escape string to `{placeholder}`. Tests in Tasks 2 and 7, and the
  `prepare_percent_round_trip` scenario in Task 14.
- **Bytes that are not UTF-8** (a latin1 column, a `BLOB`, a binary argument): they reach PHP byte for byte, and
  arguments from PHP reach the store byte for byte, never lossily converted. Test in Task 13.
